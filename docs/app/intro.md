# VELA Drive 앱 사용 설명서

## 이 문서에 대해

VELA Drive는 차량 상태를 확인하고 원격으로 제어하는 모바일 앱입니다. 이 설명서는 앱을 설치하고 차량을 연결하는 것부터 일상적인 사용, 문제가 생겼을 때의 대처까지를 다룹니다.

| 구분 | 내용 |
| --- | --- |
| 다루는 것 | 앱 설치와 차량 연결 · 차량 상태 확인 · 원격 제어 · 디지털 키 관리 · 소프트웨어 업데이트 · 정비 알림 · 데이터 관리 |
| 다루지 않는 것 | 차량 자체의 조작 방법 · 정비 작업 · 보증과 서비스 정책 |

:::note[VELA Drive는 레퍼런스 앱입니다]
VELA는 완성차 회사(OEM)에 소프트웨어 플랫폼을 공급하는 회사이며, 차량을 직접 만들지 않습니다. VELA Drive는 OEM이 자사 브랜드로 출시하기 전에 참고하는 **레퍼런스 구현체**입니다. 각 OEM은 이 앱을 커스터마이징해 자사 전용 앱으로 출시할 수 있습니다. 기능과 화면 구성은 동일하지만 색상·이름·일부 문구는 다를 수 있습니다. 이 문서는 각색 이전의 원형 기준으로 작성했습니다.
:::

- VELA 플랫폼이 적용된 차량
- iOS 16 이상 또는 Android 12 이상
- 차량에 등록할 수 있는 이메일 주소

## 표기 규약

| 등급 | 이 문서에서 쓰는 경우 |
| --- | --- |
| **경고** | 디지털 키 회수, 데이터 삭제, 되돌릴 수 없는 동작 |
| **주의** | 설치 중단, 원격 잠금 시의 주의점, 복구 가능한 상황 |
| **참고** | 알아 두면 편한 정보 |

이 문서에는 **'위험' 등급이 나오지 않습니다.** 차량 소유자는 하드웨어를 직접 만지지 않기 때문입니다.

| 표기 | 뜻 |
| --- | --- |
| **굵은 글씨** | 앱 화면에 표시된 버튼이나 메뉴의 이름 |
| **설정 > 차량** | 메뉴를 차례로 선택하는 경로 |

## 설계 노트

> 이 문서를 왜 이렇게 설계했는지에 대한 기록입니다. 실제 제품 문서에는 포함되지 않습니다.

**독자**: 차량 소유자. 자동차 정비 지식도, 소프트웨어 지식도 없다고 가정했습니다. 휴대폰 화면으로, 차 앞에 서서, 대체로 급한 상황에 읽습니다.

**구조 결정**: 1장을 "무엇을 할 수 있는가"가 아니라 **"무엇을 하고 싶은가"** 표로 시작했습니다. 기능 목록으로 시작하면 독자가 자기 문제를 기능 이름으로 번역해야 합니다. 목적을 먼저 제시하면 그 번역을 문서가 대신합니다.

**이 세트에만 용어집을 두지 않은 이유**: 차량 소유자는 용어집을 찾아보지 않습니다. 모르는 말이 나오면 문서를 덮습니다. 그래서 용어집을 만드는 대신 **본문에 어려운 용어를 아예 쓰지 않는 쪽**을 택했습니다. 'OTA'를 쓰지 않고 '소프트웨어 업데이트'로, '캘리브레이션'을 쓰지 않고 '센서 점검'으로 씁니다. 다른 세 세트에는 용어집이 있습니다.

**용어 처리**: 같은 개념을 [VELA Deploy 운영 가이드](../deploy/intro.md)에서는 '무선 업데이트(OTA)'로, [API 문서](../api/intro.md)에서는 `campaign`으로 부릅니다. 용어집에는 세 표기가 모두 등재되어 있고, 어느 문서에서 어느 표기를 쓰는지도 함께 관리합니다.

**정보 유형 분류**: DITA의 개념 · 절차 · 레퍼런스를 기준으로 각 장에 유형을 붙였습니다. 다만 이 세트에는 '개념 + 절차'가 유독 많습니다. 차 앞에 서서 휴대폰으로 읽는 독자를 두 페이지로 보낼 수 없기 때문입니다. 파일은 기능 단위로 두고 유형은 문서 안에서 섹션으로 나눴습니다. 반대로 **실패 대응은 전부 [문제 해결하기](./troubleshooting.md)로 모았습니다.** 뭔가 잘못됐을 때 독자는 기능 이름이 아니라 증상으로 찾기 때문입니다.

**다른 세트와 다르게 처리한 점**: 사용자 문서에는 안전 경고 등급 중 '위험'을 쓰지 않습니다. 사용자는 하드웨어를 직접 만지지 않기 때문입니다. 되돌릴 수 없는 동작(키 공유 회수, 세정제로 인한 코팅 손상)에만 '경고'를 쓰고, 자동 복구되는 상황(업데이트 설치 중단)은 '주의'로 낮췄습니다. 등급 정의는 [표기 규약](../#표기-규약)에 있습니다.

**의도적으로 넣지 않은 것**: 화면 스크린샷을 전제하지 않고 작성했습니다. 앱 UI는 자주 바뀌고, 스크린샷이 낡으면 문서 전체의 신뢰가 떨어집니다. 화면 요소는 이름으로 지칭하고, 위치는 필요할 때만 설명합니다.

**레퍼런스 앱이라는 설정이 문서에 미친 영향**: VELA Drive가 OEM 브랜드로 각색된다는 전제 때문에, 문서에서 브랜드 고유의 시각 요소(색상, 로고, 정확한 문구)를 설명하지 않습니다. 대신 기능의 동작 방식과 실패 조건처럼 **어떤 OEM 버전에서도 바뀌지 않는 내용**에 집중합니다. 문서가 다루는 범위를 "각색되어도 변하지 않는 것"으로 한정하면, OEM이 브랜드를 바꿔도 문서를 다시 쓸 필요가 없습니다.
