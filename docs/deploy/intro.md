# VELA Deploy 운영 가이드

VELA Deploy는 차량 소프트웨어를 단계적으로 배포하고, 문제가 생기면 되돌리는 운영 콘솔입니다. 이 문서는 배포를 담당하는 릴리스 운영자를 대상으로 합니다.

:::note
이 문서는 포트폴리오용으로 창작한 가상 제품의 문서입니다. 실재하는 제품이나 조직과 관련이 없습니다.
:::

## 핵심 개념

배포와 관련된 모든 판단은 아래 다섯 가지 개념 위에서 이루어집니다.

| 개념 | 설명 |
| --- | --- |
| 패키지 | 차량에 설치되는 소프트웨어 묶음. 서명이 검증되어야 배포할 수 있습니다. |
| 캠페인 | 하나의 패키지를 정해진 대상에 배포하는 단위. |
| 타깃 그룹 | 배포 대상 차량의 조건. 차종, 하드웨어 구성, 현재 버전으로 정의합니다. |
| 롤아웃 단계 | 대상을 넓혀 가는 순서. 예를 들어 1% → 10% → 100%입니다. |
| 게이트 | 다음 단계로 넘어갈지 판단하는 기준. 성공률과 오류율로 정의합니다. |

## 배포가 진행되는 흐름

```
패키지 업로드 → 호환성 규칙 정의 → 타깃 그룹 생성 → 캠페인 생성
      → 1단계 배포 → 게이트 판정 → 2단계 배포 → … → 완료
                          ↓ 실패
                    일시 중지 / 롤백
```

## 설계 노트

> 이 문서를 왜 이렇게 설계했는지에 대한 기록입니다.

**독자**: 릴리스 운영자. 업무 도구에는 익숙하지만 코드는 읽지 못합니다. 평소에는 절차대로 진행하고, 사고가 났을 때 급히 찾아봅니다.

**구조 결정**: 개념을 1장에 모으고 절차와 섞지 않았습니다. 배포 도구의 문서가 어려워지는 가장 흔한 이유는 절차 중간에 개념 설명이 끼어들기 때문입니다. 개념을 먼저 한 번 정리하면 이후 절차가 짧아집니다.

**5장을 독립적으로 쓰는 이유**: 사고가 났을 때 사람은 문서를 처음부터 읽지 않습니다. 문제 대응 장은 앞 장을 읽지 않아도 이해되도록 필요한 개념을 그 자리에서 다시 설명합니다. 다른 장에서는 피하는 중복을 여기서만 의도적으로 허용합니다.

**판단 기준을 표로 쓰는 이유**: "오류율이 높으면 중단합니다" 같은 서술은 급할 때 읽히지 않습니다. 숫자와 조치를 표로 제시합니다. 다만 숫자는 조직마다 다르므로 예시임을 명시합니다.

**다른 세트와 다르게 처리한 점**: 이 문서에는 '경고'가 많이 등장합니다. 배포는 되돌리기 어려운 동작이 많기 때문입니다. 반면 신체 위험은 없으므로 '위험' 등급은 쓰지 않습니다. 등급 사용 기준은 네 세트가 공유합니다.
