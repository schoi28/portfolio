# 첫 캠페인 만들어 보기

검증 환경에서 캠페인 하나를 처음부터 끝까지 만들어 봅니다. 약 30분이 걸립니다. 이 장을 마치면 이후 장의 개별 설정을 이해할 준비가 됩니다.

:::note[참고]
이 절차는 **검증 환경**에서 수행합니다. 검증 환경의 대상 차량은 실제 고객 차량이 아니라 사내 검증 플릿입니다. 프로덕션 환경에서 첫 캠페인을 만들지 마십시오.
:::

## 시작하기 전에

| 준비물 | 확인 방법 |
| --- | --- |
| 배포 담당자 권한 | **설정 > 내 권한**에서 `campaign.create` 확인 |
| 서명된 패키지 | 빌드 시스템에서 생성된 `.vpk` 파일 |
| 대상 차종 정보 | 차종 코드와 현재 소프트웨어 버전 |

## 1. 패키지 업로드하기

1. **패키지 > 새 패키지**를 선택합니다.
2. `.vpk` 파일을 업로드합니다.
3. 업로드가 끝나면 서명 검증이 자동으로 실행됩니다.

검증에 통과하면 패키지 상태가 **검증 완료**로 바뀝니다. 실패하면 배포할 수 없습니다.

| 검증 항목 | 실패 시 원인 |
| --- | --- |
| 서명 유효성 | 빌드 시스템의 서명 키가 등록되지 않음 |
| 대상 하드웨어 일치 | 패키지가 다른 하드웨어용으로 빌드됨 |
| 버전 형식 | 버전 문자열이 규칙을 따르지 않음 |

## 2. 타깃 그룹 만들기

배포 대상 차량의 조건을 정의합니다.

1. **타깃 그룹 > 새 그룹**을 선택합니다.
2. 조건을 지정합니다.

   | 조건 | 예시 값 | 설명 |
   | --- | --- | --- |
   | 차종 | `Hanul EV Sedan` | 대상 차종 |
   | 현재 버전 | `2026.8.2` | 이 버전을 쓰는 차량만 |
   | 하드웨어 구성 | `sensor_kit: none` | 센서 킷 장착 여부 |
   | 지역 | `KR` | 판매 지역 |

3. **미리보기**를 선택해 몇 대가 대상인지 확인합니다.

:::info[주의]
미리보기 숫자가 예상보다 크다면 조건이 너무 넓은 것입니다. 특히 현재 버전 조건을 비워 두면 모든 버전이 대상이 됩니다.
:::

## 3. 캠페인 만들기

1. **캠페인 > 새 캠페인**을 선택합니다.
2. 1단계에서 만든 패키지와 2단계에서 만든 타깃 그룹을 선택합니다.
3. 배포 대상 유형을 선택합니다.

   | 유형 | 선택 기준 |
   | --- | --- |
   | 중앙 연산 장치 | VELA OS 소프트웨어 업데이트 |
   | 존 ECU | 도어·공조 등 부품 펌웨어 업데이트 |

4. 롤아웃 단계를 설정합니다. 처음에는 아래 기본값을 사용하십시오.

   | 단계 | 비율 |
   | --- | --- |
   | 1단계 | 1% |
   | 2단계 | 10% |
   | 3단계 | 100% |

5. 게이트 기준을 설정합니다. 기본값은 성공률 98% 이상, 오류율 2% 이하입니다.
6. **저장**을 선택합니다.

캠페인이 저장되면 상태가 **생성됨**으로 바뀝니다.

## 4. 배포 시작하기

1. 캠페인 상세 화면에서 **배포 시작**을 선택합니다.
2. 확인 창에서 대상 차량 수와 첫 단계 비율을 다시 확인합니다.
3. **시작**을 선택합니다.

1단계 배포가 시작됩니다. 대상 차량은 조건을 만족하는 즉시 다운로드를 시작하며, 설치는 차량이 주차 상태가 되었을 때 진행됩니다.

## 5. 진행 상황 확인하기

캠페인 상세 화면에서 실시간으로 확인할 수 있습니다.

| 지표 | 의미 |
| --- | --- |
| 대상 | 이 단계의 배포 대상 차량 수 |
| 설치 완료 | 설치를 마친 차량 수 |
| 진행 중 | 다운로드 또는 설치 중인 차량 수 |
| 실패 | 설치에 실패한 차량 수 |
| 성공률 | 완료 ÷ (완료 + 실패) |

1단계는 **최소 48시간** 지켜봅니다. 그동안 진행 상황을 보면서, **설치 대기** 상태로 오래 머무는 차량이 있으면 아래 사전 조건을 만족하는지 직접 확인하십시오.

| 사전 조건 | 기본값 |
| --- | --- |
| 주차 상태 (기어 P) | 필수 |
| 구동 배터리 잔량 | 30% 이상 |
| 보조 배터리 잔량 | 40% 이상 |
| 통신 가능 | 필수 |

조건을 바꾸는 방법은 [배포 준비하기 · 사전 조건 설정하기](./prepare.md#사전-조건-설정하기)에, 48시간인 이유는 [롤아웃 운영하기 · 단계별 대기 시간](./rollout.md#단계별-대기-시간)에 있습니다.

## 6. 다음 단계로 진행하기

1단계가 끝나면 게이트가 자동으로 판정합니다.

- 기준을 만족하면 2단계로 자동 진행됩니다.
- 기준을 밑돌면 **게이트 중지** 상태가 되고, 운영자의 판단을 기다립니다.

게이트 중지 상태에서 무엇을 확인하고 어떻게 결정하는지는 [문제에 대응하기](./incident-response.md)에서 다룹니다.

## 정리

지금까지 다음을 수행했습니다.

1. 패키지를 업로드하고 서명을 검증했습니다.
2. 타깃 그룹으로 대상 차량을 좁혔습니다.
3. 롤아웃 단계와 게이트 기준을 정한 캠페인을 만들었습니다.
4. 배포를 시작하고 진행 상황을 확인했습니다.

각 단계의 설정을 실제 운영 수준으로 다듬는 방법은 [배포 준비하기](./prepare.md)에서 이어집니다.
