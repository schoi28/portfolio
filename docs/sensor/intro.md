# VELA Sense 설치 가이드

:::danger[위험]
라이다가 동작 중일 때 루페·쌍안경·망원 렌즈 등 **확대 광학 기기로 광학창을 들여다보지 마십시오**. 실명에 이를 수 있습니다(Class 1M, IEC 60825-1). 모듈을 분해하지 말고, 점검은 전원을 차단한 뒤 수행하십시오.
:::

## 이 문서에 대해

VELA Sense 레퍼런스 센서 킷을 차량에 장착하고, 배선하고, 캘리브레이션해 정상 동작을 확인하기까지의 전 과정을 다룹니다.

| 구분 | 내용 |
| --- | --- |
| 다루는 것 | 장착 위치 선정 · 기구 장착 · 배선 · 전원 인가 · 캘리브레이션 · 정기 점검 · 현장 진단 |
| 다루지 않는 것 | 센서 데이터의 활용(→ [VELA Vehicle API](../api/intro.md)) · 차량 플랫폼 소프트웨어 설치 · OEM 양산 차량의 센서 구성 |
| 적용 대상 | VELA Sense 킷 R2 (LR-40 라이다 · CM-20 카메라 · 인터페이스 박스 IB-2) |
| 작업 환경 | 개발·검증 차량. 양산 차량에는 적용하지 않습니다 |

## 대상 독자

차량에 하드웨어를 직접 장착하는 현장 엔지니어를 기준으로 썼습니다. **자율주행 시스템에 대한 사전 지식은 전제하지 않습니다.**

| 역할 | 하는 일 | 먼저 읽을 곳 |
| --- | --- | --- |
| **현장 설치 엔지니어** | 차량에 센서를 장착하고 배선한다 | [VELA Sense란](./overview.md) → [설치 계획 세우기](./planning.md) |
| **검증 엔지니어** | 캘리브레이션을 수행하고 합격 여부를 판정한다 | [캘리브레이션하기](./calibration.md) · [사양 확인하기](./specifications.md) |
| **차량 관리 담당자** | 장착된 킷을 정기 점검하고 모듈을 교체한다 | [점검하고 관리하기](./maintenance.md) · [문제 해결하기](./troubleshooting.md) |
| **통합 담당 개발자** | 센서 상태를 소프트웨어에서 읽는다 | [VELA Vehicle API · 센서 상태 조회하기](../api/sensors.md) |

전제하는 숙련도는 다음과 같습니다.

- 차량 내장재 탈거와 복원, 토크 렌치 사용, 하네스 배선에 숙련되어 있을 것
- 멀티미터로 도통과 단락을 확인할 수 있을 것
- 노트북으로 설정 도구를 실행할 수 있을 것. **명령줄 사용은 전제하지 않습니다.**

## 표기 규약

### 안내 상자

| 등급 | 이 문서에서의 쓰임 |
| --- | --- |
| **위험** | 레이저 광원, 에어백 전개 경로, 화재 — 사망이나 중상에 이르는 경우 |
| **경고** | 12V 전기 작업, 하네스 손상, 모듈 교체 후 미보정 — 되돌릴 수 없는 손상 |
| **주의** | 허용 오차 이탈, 재작업이 필요한 실수 — 복구 가능한 오류 |
| **참고** | 알아 두면 작업이 수월해지는 정보 |

전체 등급 정의는 [표기 규약](../#표기-규약)에 있습니다. 네 문서 세트가 같은 기준을 씁니다.

### 글자 표기

| 표기 | 뜻 |
| --- | --- |
| **굵은 글씨** | 화면이나 장비에 표시된 요소의 이름 |
| **설정 > 센서** | 메뉴를 차례로 선택하는 경로 |
| `LR-40` | 모델명, 커넥터 이름, 파일 이름 |
| 18 N·m ± 2 | 값과 허용 오차. 허용 오차가 적힌 수치는 반드시 측정해 확인합니다 |

## 설계 노트

> 이 문서를 왜 이렇게 설계했는지에 대한 기록입니다. 실제 제품 문서에는 포함되지 않습니다.

**독자**: 현장 엔지니어. 하드웨어 작업에는 숙련되어 있지만 소프트웨어와 네트워크 지식은 낮습니다. 작업 현장에서 태블릿으로, 장갑을 낀 손으로, 조명이 나쁜 곳에서 읽습니다.

**구조 결정**: 이 읽는 환경이 문서 구조를 결정했습니다. 한 화면에 한 작업 단위가 들어가도록 절을 잘게 나누고, 긴 문단 대신 표를 씁니다. 수치에는 항상 단위와 허용 오차를 함께 씁니다.

**머리말과 1장을 나눈 이유**: 머리말은 **이 문서를 어떻게 읽을지**에 대한 정보이고, 1장은 **제품이 무엇인지**에 대한 정보입니다. 둘을 한 페이지에 두면 "내가 읽을 문서인가"를 판단하려는 독자와 "이 제품이 무엇인가"를 알고 싶은 독자가 같은 글을 읽어야 합니다. 머리말은 한 번 읽고 다시 보지 않지만 1장은 작업 중에 되돌아옵니다.

**정보 유형 분류**: 장착부터 캘리브레이션까지는 **되돌릴 수 없는 물리 작업 순서**를 그대로 따르는 절차 문서입니다. 치수·토크·합격 기준처럼 현장에서 찾아보는 값은 [사양 확인하기](./specifications.md)에 모았습니다. 작업 중에 값을 확인하려고 긴 절차를 스크롤하게 두지 않기 위해서입니다. 캘리브레이션만 '개념 + 절차'인데, 왜 필요한지 모르면 합격 기준을 자의적으로 완화하기 때문입니다.

**안전 경고를 앞에 몰아 쓰지 않는 이유**: 문서 첫머리에 경고를 모아 두면 독자는 그 페이지를 한 번 넘긴 뒤 다시 보지 않습니다. 각 작업 단계 바로 앞에 해당 경고를 반복 배치합니다. 중복이지만 이 문서에서는 의도적입니다.

**네 세트 중 유일하게 '위험' 등급을 쓰는 문서**: 신체 위험이 실재하기 때문입니다. 다만 '위험'은 레이저 광원·에어백 전개 경로·화재처럼 **사망이나 중상에 이르는** 경우로만 한정했습니다. 12V 전기 작업이나 하네스 손상은 되돌릴 수 없는 장비 손상이므로 '경고'입니다. 다른 세트에서 '위험'을 쓰지 않는 것도 같은 기준의 결과입니다.

**용어집을 따로 둔 이유**: 이 문서의 독자는 기계 작업에 숙련되어 있지만 네트워크와 시간 동기화는 처음일 수 있습니다. GMSL2, PTP, 외재 파라미터 같은 용어를 본문에서 매번 풀어 쓰면 숙련자에게는 군더더기가 됩니다. 한 곳에 모으고 첫 등장에서만 연결합니다.

**다른 문서와의 연결**: 여기서 수행한 캘리브레이션 결과는 [API 문서](../api/intro.md)의 센서 상태 조회로 확인할 수 있고, 청소 시기는 [VELA Drive 앱](../app/intro.md)의 센서 청소 알림으로 사용자에게 전달됩니다.
