# Work

문서 세 종을 하나의 제품군으로 묶어 작성했습니다. 서로 다른 독자와 문서 유형을 다루면서도, 실제 제품 조직에서처럼 용어와 정보 구조가 일관되게 유지되는지 보여주기 위해서입니다.

## 가상 제품군: Aeris

실내 공기질을 측정하고 관리하는 제품군입니다.

| 문서 | 제품 | 주 독자 | 문서 유형 |
| --- | --- | --- | --- |
| [하드웨어 매뉴얼](./hardware/intro.md) | Aeris Sense S1 (센서 기기) | 최종 사용자 | 튜토리얼 · 트러블슈팅 |
| [소프트웨어 매뉴얼](./software/intro.md) | Aeris Console (관리 웹) | 시설 관리자 | 하우투 가이드 |
| [API · SDK 문서](./api/intro.md) | Aeris API v1 | 개발자 | 레퍼런스 |

## 왜 하나의 제품군으로 묶었나

문서 샘플을 서로 무관한 제품으로 만들면 각각의 완성도만 보입니다. 하나의 제품군으로 묶으면 다음을 함께 보여줄 수 있습니다.

- **용어 일관성**: 세 문서가 같은 용어집을 공유합니다. 기기는 항상 '센서', 설치 단위는 항상 '설치 지점'입니다.
- **독자별 분기**: 같은 기능을 최종 사용자·관리자·개발자에게 각각 다른 깊이로 설명합니다.
- **상호 참조**: 하드웨어 설치가 끝나면 콘솔 등록으로, 콘솔에서 다루기 어려운 작업은 API로 연결됩니다.

## 문서 유형 체계

Diátaxis 프레임워크를 기준으로 문서 유형을 나눴습니다. 자세한 판단 기준은 [How I work](/how-i-work)에 정리했습니다.
