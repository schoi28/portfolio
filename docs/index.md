# Work

하나의 제품군을 네 종류의 독자에게 각각 다르게 설명한 문서 세트입니다.

:::note

:::

## 가상 제품군: VELA

VELA는 차량용 소프트웨어 플랫폼을 공급하는 회사입니다. 완성차 회사(OEM)에 차량 소프트웨어 플랫폼을 납품하고, 협력사가 그 위에서 기능을 개발합니다.

## 왜 하나의 제품군으로 묶었나

문서 샘플을 서로 무관한 제품으로 만들면 각 문서의 완성도만 보입니다. 하나의 제품군으로 묶으면 다음을 함께 보여줄 수 있습니다.

**독자에 따라 문서가 얼마나 달라지는가.** 같은 무선 업데이트를 네 문서가 각각 다르게 다룹니다. 차량 소유자에게는 "업데이트 알림이 뜨면 무엇을 해야 하는지", 운영자에게는 "어느 범위까지 배포를 확대할지 판단하는 기준", 개발자에게는 "캠페인 생성 API의 요청 형식", 현장 엔지니어에게는 "센서 펌웨어를 수동으로 복구하는 절차"입니다.

**용어가 일관되는가.** 네 문서가 하나의 용어집을 공유합니다. 다만 독자에 따라 노출하는 용어가 다릅니다. 개발자 문서의 `campaign`은 운영자 문서에서 '캠페인'이고, 사용자 문서에는 아예 등장하지 않습니다.

**문서끼리 연결되는가.** 센서를 장착하고, 그 위에서 플랫폼이 돌고, 개발자가 API로 접근하고, 운영자가 소프트웨어를 배포하고, 소유자가 앱에서 확인합니다.

## 각 문서의 설계 근거

문서마다 "설계 노트"를 붙였습니다. 독자를 어떻게 정의했고, 왜 그런 구조를 선택했으며, 다른 문서와 무엇을 다르게 처리했는지 적었습니다. 판단 기준 전체는 [How I work](/how-i-work)에 정리했습니다.

## 전체 구조

![VELA Cloud와 차량 내부 구성의 연결 구조](/img/architecture-overview.svg)

VELA는 완성차 회사에 소프트웨어 플랫폼을 공급하는 회사이며, 차량을 직접 만들지 않습니다. 네 문서 세트는 이 구조에서 각각 다른 지점을 다룹니다.

| 세트 | 다루는 지점 | 분량 |
| --- | --- | --- |
| VELA Drive 앱 | 최종 사용자가 쓰는 앱 | 9개 장 |
| VELA Vehicle API | VELA Cloud가 노출하는 인터페이스 | 9개 장 |
| VELA Deploy | 소프트웨어를 차량에 배포하는 운영 콘솔 | 7개 장 |
| VELA Sense | 개발·검증 차량에 장착하는 센서 킷 | 10개 장 |
