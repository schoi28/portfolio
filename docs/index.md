# Sample Docs

하나의 가상 제품군을 네 종류의 독자에게 각각 다르게 설명한 문서 세트입니다.

:::note[참고]
VELA는 이 문서를 위해 설계한 가상의 회사이며, 실재하는 제품이나 조직과 관련이 없습니다.
:::

## 가상 제품군 VELA

### VELA는 어떤 회사인가

VELA는 **차량용 소프트웨어를 만들어 완성차 회사에 공급하는 회사**입니다. 차를 직접 만들지는 않습니다.

현대·기아·테슬라 같은 완성차 회사(OEM)가 차를 만들고, VELA는 그 차 안에서 돌아가는 소프트웨어 플랫폼을 납품합니다. 완성차 회사의 협력사 개발자들은 그 플랫폼 위에서 자기 기능을 개발합니다. 차가 출고된 뒤에는 VELA의 서버에서 소프트웨어를 무선으로 업데이트하고, 차량 소유자는 모바일 앱으로 자기 차의 상태를 봅니다.

![VELA Cloud와 차량, 모바일 앱의 연결 구조](/img/architecture-overview.svg)

센서를 차량에 장착하고(**VELA Sense**), 그 위에서 소프트웨어 플랫폼이 돌고, 개발자가 데이터에 접근하고(**Vehicle API**), 운영자가 새 소프트웨어를 차량에 배포하고(**VELA Deploy**), 소유자가 앱에서 결과를 확인합니다(**VELA Drive**).

| 세트 | 다루는 지점 | 분량 |
| --- | --- | --- |
| VELA Drive 앱 | 최종 사용자가 쓰는 앱 | 9개 장 |
| VELA Vehicle API | VELA Cloud가 노출하는 인터페이스 | 9개 장 |
| VELA Deploy | 소프트웨어를 차량에 배포하는 운영 콘솔 | 7개 장 |
| VELA Sense | 개발·검증 차량에 장착하는 센서 킷 | 10개 장 |

이 구조 때문에 VELA의 고객은 한 종류가 아닙니다. **완성차 회사, 협력사 개발자, 그 차를 산 일반 소비자, 그리고 개발·검증 차량을 다루는 현장 엔지니어**가 모두 VELA의 문서를 읽습니다.

## 표기 규약

네 문서 세트는 아래 네 등급의 안내 상자를 공유합니다. 등급은 **피해의 크기와 되돌릴 수 있는지**로 정합니다.

| 등급 | 의미 |
| --- | --- |
| **위험** | 피하지 않으면 **사망이나 중상에 이르는** 급박한 위험 (고전압, 레이저 광원, 화재, 움직이는 차량) |
| **경고** | 피하지 않으면 **상해, 중대한 데이터 손실, 되돌릴 수 없는 장비 손상**으로 이어질 수 있는 상황 |
| **주의** | 피하지 않으면 **경미한 상해, 복구 가능한 오류, 데이터 품질 저하**로 이어질 수 있는 상황 |
| **참고** | 위험 상황이 아니며, 알아 두면 결과가 나아지는 정보 |

세트마다 쓰는 등급이 다릅니다. 신체 위험이 실재하는 [VELA Sense 설치 가이드](./sensor/intro.md)만 '위험'을 쓰고, 나머지 세 세트는 '경고' 이하만 사용합니다. 같은 기준을 적용한 결과입니다.

작업 수행 중에 알아야 할 내용이 아니라 **수행하기 전에 알아야 할 내용**이면, 해당 절의 첫 단계 앞에 둡니다.

## 각 문서의 설계 근거

문서마다 "설계 노트"를 붙였습니다. 독자를 어떻게 정의했고, 왜 그런 구조를 선택했으며, 다른 문서와 무엇을 다르게 처리했는지 적었습니다. 실무에서의 판단 기록은 [Portfolio](/projects)에 있습니다.
