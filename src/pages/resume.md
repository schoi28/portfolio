# Resume

DBMS와 자율주행 솔루션 분야에서 국문·영문 기술 문서를 작성해 온 테크니컬 라이터입니다. 2023년 11월부터 제품 레퍼런스, 사용자·설치 가이드, API 문서, 릴리스 노트 등을 작성했습니다. 문서를 쓰는 일에서 그치지 않고, **문서가 고객사별로 정확하게 조립되고 제품이 바뀌어도 검수되며 동료가 이어서 작업할 수 있는 체계를 만드는 데** 강점이 있습니다. 두 언어 모두 각 언어로 직접 쓰고, 문서에 따라 두 언어 사이를 번역합니다.

## 경력

### 자율주행 솔루션 소프트웨어 회사 · Technical Writer

**2025년 1월 ~ 현재**

제품 5종으로 구성된 자율주행 솔루션의 영문 사용자 문서를 담당하고 있습니다. 기존 문서가 없거나 여러 곳에 흩어져 있던 상황에서 문서 체계를 통합하고, 문서 작성과 검수에 필요한 도구를 직접 개발했습니다.

- **문서 체계 설계 및 집필**: 솔루션 매뉴얼과 제품별 매뉴얼로 구성된 2단계 문서 체계를 설계하고 작성했습니다. 총 171편의 문서와 이미지 310장, 약 18만 7천 단어 규모이며, 이 중 128편(약 75%)을 새로 작성했습니다.
- **국문 문서 운영**: 사내 공유용 국문 문서를 Confluence에서 별도로 관리했습니다.
- **독자 분석 및 문서 설계**: 독자를 세 가지 유형으로 구분하고, 유형별 사전 지식 수준을 정의해 모든 제품 문서에 일관되게 적용했습니다.
- **작성 원칙 및 표준 적용**: 용어집 정책을 포함한 세 가지 작성 원칙을 수립하고 모든 제품에 공통 적용했습니다. IEC/IEEE 82079-1을 참고해 문서 구조를 전반적으로 재정비했습니다.
- **문서 생성 환경 개발**: 정적 사이트 생성기를 직접 개발해 하나의 원본에서 웹 문서와 PDF를 함께 생성하도록 구현했습니다. 생성된 문서는 인터넷 연결 없이도 사용할 수 있습니다.
- **조건부 콘텐츠 시스템 구축**: 고객사별·내부용 여부·기능별 조건에 따라 문서 내용을 구분해 출력하는 시스템을 설계했습니다. 각 산출물에 지정된 범위의 콘텐츠만 포함되는지 검증하는 단계도 구현했습니다.
- **API 문서 자동화**: OpenAPI 명세에서 API 레퍼런스를 생성하는 파이프라인을 구축하고, 변경 사항을 diff 리포트로 확인할 수 있도록 했습니다.
- **문서 검수 자동화**: 링크와 앵커가 실제로 존재하는지 파일 간 교차 검증하고, 조건부 콘텐츠 마커 구조를 검사하는 단계를 빌드에 포함했습니다. 자동 수정 범위는 의도적으로 제한하고 위치와 근거만 보고하도록 설계했습니다.
- **비작성자용 빌드 환경**: 명령줄을 쓰지 않는 구성원도 문서를 빌드하고 검사할 수 있도록 웹 GUI를 만들었습니다.
- **문서 기여 환경 개선**: 다른 구성원이 문서 작업에 참여할 수 있도록 설정 가이드와 작성 가이드를 마련했습니다. 가이드는 기능 목록이 아니라 작성자가 하려는 일을 기준으로 구성했습니다.
- **콘텐츠 판단 기준 수립**: Confluence에 Technical Writing Guide를 작성해, 어떤 정보를 본문·부록·레퍼런스에 두고 무엇을 문서 범위 밖으로 둘지 팀이 같은 기준으로 판단할 수 있게 했습니다.
- **리뷰 프로세스 개선**: Google Docs 기반 리뷰를 Markdown과 Pull Request 중심으로 전환했습니다. 그 결과, 이전에 지연되던 리뷰 대부분이 1~2일 내에 완료됐습니다.

### DBMS 소프트웨어 회사 · Technical Writer

**2023년 11월 ~ 2024년 12월**

DBMS 제품 매뉴얼 전반을 국문과 영문으로 작성·관리했습니다. 문서는 GitHub 공개 저장소에서 버전 관리되는 환경이었습니다.

- **기술 문서 작성**: SQL 레퍼런스, API·JDBC·CLI 매뉴얼, 복제·로그 분석기 매뉴얼, 도구 매뉴얼, 설치 가이드, 릴리스 노트 및 패치 노트 등 31종의 문서를 작성하고 갱신했습니다.
- **국문·영문 문서 운영**: 영문 번역본이 없던 매뉴얼의 영문판을 새로 만들었습니다. 이후에는 국문 수정과 영문 반영을 하나의 Pull Request에서 처리해, 두 언어가 같은 diff에 올라오도록 관리했습니다.
- **다중 버전 동시 관리**: 같은 매뉴얼이 `7.1`·`7.3`·`trunk` 세 버전 트리에 존재해, 변경 한 건을 국문·영문 × 세 버전에 함께 반영했습니다.
- **기존 문서 품질 개선**: 번역과 갱신 과정에서 설명이 부정확하거나 두 가지로 읽히는 문장을 발견하면 번역본만 다듬지 않고 국문 원문까지 고쳤습니다.
- **용어 일관성 관리**: 용어를 변경할 때 해당 용어가 등장하는 모든 문서를 찾아 함께 반영했습니다.
- **협업 및 변경 추적**: [ALTIBASE/Documents](https://github.com/ALTIBASE/Documents) 저장소의 Collaborator로서 Pull Request 113건을 제출해 101건을 병합했습니다. 각 PR을 이슈 트래커의 요청 번호와 연결하고, 리뷰 코멘트를 항목별로 반영했습니다.
- **문서 사이트 구축**: MkDocs와 Read the Docs를 활용해 새 웹 매뉴얼 사이트를 구축했습니다. 이때 확인한 공개 도구의 한계가 이후 자체 생성기로 전환하는 판단의 근거가 됐습니다.

## 개인 프로젝트

### 가상 제품군 VELA 문서 세트

현 직장의 산출물이 대외비여서, 실무와 유사한 복잡도의 가상 제품군을 직접 설계하고 문서 세트 전체를 혼자 완성했습니다.

- **문서 44편 · 약 9만 2천 자 · 다이어그램 19종.** 차량 소유자, 릴리스 운영자, 개발자, 현장 엔지니어 네 독자를 각각 다른 문서 유형과 깊이로 대응했습니다.
- **품질 기준을 설정 파일로 분리**했습니다. 용어집 79개 항목, 스타일 룰, 독자 정의, 경고 등급 체계가 본문이 아니라 `_config/`에 있습니다.
- **그 설정을 읽어 문서를 검사하는 스크립트**를 만들어 빌드 앞단에 연결했습니다. 금지 표현, 독자 수준에 맞지 않는 용어, 절차 단계 수, 안내 상자 등급, 번호 목록 구조, 링크와 앵커의 실재 여부를 검사합니다.
- **번역 정합성도 같은 도구가 검사합니다.** 국문을 원문, 영문을 번역본으로 선언하면 제목·표·이미지·링크·안내 상자의 개수와 제목 단계를 대조하고, 번역되지 않은 한글이 남았는지와 원문이 번역본보다 나중에 바뀌었는지를 판정합니다.
- **GitHub Actions에 연결**해, 검수에서 오류가 하나라도 나오면 빌드와 배포가 중단되도록 했습니다.
