# VELA Vehicle API 개발자 가이드

:::note[참고]
이 페이지는 제품 문서가 아니라, 그 문서를 어떻게 설계했는지에 대한 기록입니다. 실제 매뉴얼은 다음 장부터 시작합니다.
:::

## 어떻게 설계했나

| 설계 기준 | 결정 |
| --- | --- |
| **핵심 독자** | VELA를 자사 서비스에 연동하는 개발자 |
| **사전 지식** | REST·OAuth는 알지만 차량 전장과 VELA 제품은 처음이라고 가정 |
| **읽는 방식** | 순서대로 읽기보다 필요한 기능이나 값을 검색해 찾아봄 |
| **설계 방향** | 제품의 데이터 모델을 먼저 이해시키고, 절차와 참조 정보를 분리 |

### 데이터 모델을 먼저 이해시키기

개발자가 API를 사용하려면 엔드포인트 목록보다 **어떤 리소스가 있고 서로 어떻게 연결되는지**를 먼저 이해해야 합니다. 따라서 1장에 리소스 모델과 시스템 아키텍처를 배치하고, 이후 장에서 개별 기능과 사용 방법을 설명했습니다.

또한 독자가 갖춰야 할 사전 지식의 범위를 머리말에 명시했습니다. REST API와 OAuth 2.0에 대한 기본 지식은 전제하되, VELA 플랫폼과 차량 도메인에 대한 사전 지식은 요구하지 않았습니다.

이를 통해 **독자가 이미 알고 있는 내용에 대한 반복 설명은 줄이고, 새로운 제품과 도메인을 이해하는 데 필요한 정보에 집중**하도록 구성했습니다.

### 사용 절차와 조회용 정보 분리하기

차량 데이터 조회나 원격 명령은 작업별 장에서 설명하고, 반복해서 찾아볼 값은 [레퍼런스 찾아보기](./reference.md)에 모았습니다. 차량이 보고하는 데이터 항목의 전체 목록인 **시그널 카탈로그**를 절차에서 분리한 것도 같은 이유입니다.

**어떻게 호출하는가**는 기능을 처음 구현할 때, **어떤 값이 있는가**는 구현 도중 반복해서 찾는 정보이기 때문입니다.

### 개발자에게 낯선 자동차 용어 설명하기

HTTP 메서드나 `vehicle_id`처럼 개발자에게 익숙한 요소보다 CCU, 존 ECU, OTA 캠페인 같은 **차량 도메인 용어**를 먼저 설명하도록 용어집을 구성했습니다. OEM·협력사 개발자와 운영자가 같은 대상을 다르게 부르는 경우에는 용어 대응표를 제공했습니다.

### SDK를 엔드포인트마다 반복하지 않기

공식 SDK 사용법은 장마다 언어별 예시를 병렬로 두는 대신 한 장에 모으고, **REST 동작과 메서드의 대응표**로 연결했습니다. 같은 예시를 두 벌로 유지하면 한쪽만 고치는 일이 반드시 생기기 때문입니다.

### 운영 환경의 차이와 변경 가능성 고려하기

VELA는 연동을 시험하는 **스테이징 환경**과 실제 차량이 연결된 **프로덕션 환경**을 따로 제공합니다. 두 환경에서 달라지는 조건을 미리 설명해, 스테이징에서는 통과했지만 프로덕션에서 처음 겪는 실패를 줄이도록 했습니다.

## 이 매뉴얼의 머리말

위 판단을 적용해 만든 머리말입니다. 실제 매뉴얼에서는 아래 내용이 1장 앞에 놓입니다.

### 이 문서에 대해

VELA Cloud가 외부에 노출하는 REST API의 개발자 가이드입니다. 차량 데이터를 조회하고, 원격 명령을 보내고, 소프트웨어 배포를 제어하는 방법을 다룹니다.

| 구분 | 내용 |
| --- | --- |
| 다루는 것 | 인증 · 공식 SDK · 차량 데이터 조회 · 원격 명령 · 센서 상태 · OTA 캠페인 · 웹훅 · 에러 처리 |
| 다루지 않는 것 | 차량 내부 통신(존 ECU, VELA OS 내부 API) · 운영 콘솔의 화면 조작(→ [VELA Deploy](../deploy/intro.md)) · 센서 장착(→ [VELA Sense](../sensor/intro.md)) |
| API 버전 | `v1` |
| 기본 URL | `https://api.vela.example.com/v1` |

### 대상 독자

VELA 플랫폼을 자사 시스템에 연동하는 개발자를 기준으로 썼습니다. **REST와 OAuth 2.0은 알고 있다고 전제하지만, VELA 제품은 처음이라고 가정합니다.**

| 역할 | 하는 일 | 먼저 읽을 곳 |
| --- | --- | --- |
| **OEM 애플리케이션 개발자** | 자사 브랜드 앱에서 차량 데이터를 쓴다 | [VELA Vehicle API란](./overview.md) → [빠르게 시작하기](./quickstart.md) → [차량 데이터 조회하기](./vehicle-data.md) |
| **협력사 개발자** | VELA 플랫폼 위에서 기능을 개발한다 | [원격 명령 보내기](./remote-commands.md) · [웹훅으로 이벤트 받기](./webhooks.md) |
| **릴리스 자동화 담당자** | 배포를 콘솔이 아니라 코드로 수행한다 | [OTA 배포 제어하기](./ota.md) · [VELA Deploy 운영 가이드](../deploy/intro.md) |
| **검증 엔지니어** | 개발 차량의 센서 상태를 확인한다 | [센서 상태 조회하기](./sensors.md) · [VELA Sense 설치 가이드](../sensor/intro.md) |

전제하는 지식은 다음과 같습니다.

- HTTP 메서드와 상태 코드, JSON 읽고 쓰기
- OAuth 2.0 클라이언트 자격 증명 흐름
- 비동기 처리(폴링 또는 웹훅 수신)를 구현할 수 있을 것

**자율주행이나 차량 전장 구조에 대한 사전 지식은 전제하지 않습니다.** 필요한 개념은 [VELA Vehicle API란](./overview.md)와 [용어 찾아보기](./glossary.md)에서 설명합니다.

### 표기 규약

#### 안내 상자

| 등급 | 이 문서에서 쓰는 경우 |
| --- | --- |
| **경고** | 자격 증명 유출, 되돌릴 수 없는 명령, 중대한 피해로 이어지는 경우 |
| **주의** | 토큰 만료, 중복 이벤트, 복구 가능한 오류 |
| **참고** | 알아 두면 구현이 수월해지는 정보 |

이 문서에서는 신체 위험을 다루지 않으므로 **'위험' 등급을 사용하지 않습니다.**

#### 글자 표기

| 표기 | 뜻 |
| --- | --- |
| `GET /vehicles` | 메서드와 경로 |
| `vehicle_id` | 파라미터·필드 이름 |
| `{vehicle_id}` | 값을 바꿔 넣는 자리 |
| **굵은 글씨** | 콘솔 화면에 표시된 요소의 이름 |

예시 요청은 `curl`로 적습니다. SDK 사용법과 메서드 대응표는 [SDK로 연동하기](./sdk.md)에 모았습니다.
