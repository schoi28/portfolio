# VELA Vehicle API란

차량 데이터를 조회하고 원격 명령을 보내는 REST API입니다.

```
https://api.vela.example.com/v1
```

VELA는 완성차 회사(OEM)에 차량 소프트웨어 플랫폼을 공급하는 Tier 1 공급사입니다. 이 API는 VELA Cloud가 노출하는 인터페이스로, OEM의 자체 시스템과 VELA Drive(레퍼런스 앱)가 동일하게 사용합니다. **VELA Drive 앱의 모든 기능은 이 API로 구현할 수 있습니다.** 여기에 없는 기능이 필요하면 [문의](#문의와-지원)해 주십시오.

## 리소스 모델

다른 문서에서 부르는 이름과 API 리소스는 다음과 같이 대응합니다.

| API 리소스 | 운영 콘솔 용어 | 앱 화면 표현 | 설명 |
| --- | --- | --- | --- |
| `vehicle` | 차량 | 내 차량 | 등록된 차량 한 대 |
| `signal` | 시그널 | (노출 안 함) | 차량이 보고하는 데이터 항목 |
| `command` | 원격 명령 | 빠른 제어 | 차량에 보내는 지시 |
| `campaign` | 캠페인 | 소프트웨어 업데이트 | 배포 단위 |
| `sensor` | 센서 | (노출 안 함) | VELA Sense로 장착된 센서 모듈 |
| `zone` | 존 | (노출 안 함) | 차량 내 물리적 구역 (전방·후방·좌측·우측) |

## 시스템 안에서 맡는 자리

![VELA Vehicle API가 시스템 전체에서 담당하는 구간](/img/api-architecture.svg)

이 API는 VELA Cloud와 그 위의 애플리케이션 사이의 경계입니다. CCU 이하의 차량 내부 통신(존 ECU, VELA Sense와의 통신)은 이 API의 범위 밖이며, VELA OS가 처리합니다.

## 구현 전에 알아야 할 것

아래 세 가지는 일반적인 웹 API와 다른 부분입니다. 모르고 구현하면 **스테이징에서는 통과하고 프로덕션에서 실패합니다.**

### 차량은 항상 연결되어 있지 않습니다

지하 주차장에 있거나 배터리 보호 모드에 들어가면 통신이 끊깁니다. 그래서 이 API의 조회는 "차량에 지금 물어보는" 것이 아니라 **차량이 마지막으로 보고한 값을 돌려주는** 방식입니다. 모든 응답에 `reported_at`이 함께 옵니다.

:::info[주의]
`reported_at`을 확인하지 않고 값을 그대로 쓰면, 사용자에게 몇 시간 전 배터리 잔량을 현재 값처럼 보여 주게 됩니다. 화면에 값을 표시할 때는 보고 시각을 함께 노출하십시오.
:::

### 원격 명령은 즉시 끝나지 않습니다

조회와 달리 명령은 결과를 바로 돌려주지 않습니다.

![원격 명령이 비동기로 처리되는 과정](/img/api-command-flow.svg)

:::warning[경고]
`202 Accepted`는 요청을 받았다는 뜻일 뿐, 차량이 명령을 수행했다는 뜻이 아닙니다. 이 응답을 성공으로 처리하지 마십시오.
:::

차량이 연결되어 있지 않으면 명령은 대기열에 머물다가 만료됩니다. **`202`를 성공으로 처리하면 안 됩니다.** 자세한 처리 방식은 [원격 명령 보내기](./remote-commands.md)에 있습니다.

### 스테이징은 사전 조건을 검사하지 않습니다

스테이징 환경의 시뮬레이션 차량은 `vehicle_id`가 `sim_`으로 시작합니다. 원격 명령을 보내면 2초의 지연 후 **항상 성공 응답**을 반환하며, 주차 여부나 배터리 잔량 같은 사전 조건 검사는 건너뜁니다.

:::warning[경고]
이 때문에 "주차 상태가 아니어서 실패" 같은 응답을 프로덕션에서 처음 만나게 됩니다. 실패 경로는 [명령별 사전 조건](./remote-commands.md#명령별-사전-조건)과 [에러 코드](./reference.md#에러-코드)를 보고 미리 구현하십시오.
:::

## 요청과 응답 형식

| 항목 | 규격 |
| --- | --- |
| 프로토콜 | HTTPS만 지원. **TLS 1.2 이상** |
| 요청 본문 | `application/json`, UTF-8 |
| 응답 본문 | `application/json`, UTF-8 |
| 시각 | RFC 3339 (`2026-03-04T18:22:31Z`). 모든 시각은 UTC |
| 단위 | SI 단위. 거리 km, 온도 °C, 전력 kW, 비율 percent |
| 식별자 | 문자열. 숫자로 파싱하지 마십시오 |
| 알 수 없는 필드 | 응답에 새 필드가 추가될 수 있습니다. 무시하도록 구현하십시오 |

## 환경

| 환경 | 기본 URL | 용도 |
| --- | --- | --- |
| 스테이징 | `https://api.staging.vela.example.com/v1` | 통합 개발과 테스트. 시뮬레이션된 차량 데이터를 반환합니다 |
| 프로덕션 | `https://api.vela.example.com/v1` | 실제 차량과 통신합니다 |

자격 증명은 환경마다 별도로 발급받아야 합니다. 스테이징 토큰은 프로덕션에서 동작하지 않습니다.

## SDK와 지원 런타임

직접 HTTP를 호출해도 되지만, 인증·재시도·폴링이 구현된 SDK를 권장합니다.

| SDK | 지원 범위 | 용도 |
| --- | --- | --- |
| Python | 3.9 이상 | 서버 애플리케이션, 분석 스크립트 |
| Node.js | 18 LTS 이상 | 웹 백엔드 |
| Java | 17 이상 | OEM 기간계 연동 |
| C++ | C++17, Linux (aarch64 · x86_64) | 차량 내 애플리케이션 |

:::note[참고]
REST API 자체는 HTTP 클라이언트가 있는 어떤 환경에서도 호출할 수 있습니다. 위 표는 **SDK를 제공하는 런타임**의 목록입니다.
:::

## 레이트 리밋과 에러

| 항목 | 요약 | 자세히 |
| --- | --- | --- |
| 레이트 리밋 | 클라이언트당 분당 600회. 초과 시 `429` | [레퍼런스](./reference.md#레이트-리밋) |
| 에러 형식 | 모든 실패 응답은 `error.code`와 `error.message`를 포함 | [레퍼런스](./reference.md#에러-코드) |
| 페이지네이션 | 커서 기반. `next_cursor`가 없으면 마지막 페이지 | [레퍼런스](./reference.md#페이지네이션) |

## 버전 정책

- API 버전은 URL 경로(`/v1`)로 표시합니다.
- 하위 호환을 깨는 변경(필드 제거, 타입 변경, 필수 파라미터 추가)이 있을 때만 버전을 올립니다. 필드 추가는 버전을 올리지 않습니다.
- 이전 버전은 새 버전 출시 후 **최소 18개월** 지원합니다. 지원 종료 6개월 전에 등록된 이메일로 안내합니다.
- 지원 종료 일정은 [레퍼런스 · 변경 이력](./reference.md#변경-이력)에서 확인할 수 있습니다.
