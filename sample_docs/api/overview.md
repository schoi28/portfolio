# VELA Vehicle API란

VELA Cloud의 차량 데이터를 조회하고 원격 명령·소프트웨어 배포를 제어하는 REST API입니다. REST 요청을 직접 보내거나 공식 SDK를 사용할 수 있습니다.

```
https://api.vela.example.com/v1
```

VELA는 완성차 회사(OEM)에 차량 소프트웨어 플랫폼을 공급하는 Tier 1 공급사입니다. 이 API는 VELA Cloud가 노출하는 인터페이스로, OEM의 자체 시스템과 VELA Drive(레퍼런스 앱)가 동일하게 사용합니다. **VELA Drive 앱의 모든 기능은 이 API로 구현할 수 있습니다.** 여기에 없는 기능이 필요하면 [문의](#문의와-지원)해 주십시오.

## 리소스 모델

다른 문서에서 부르는 이름과 API 리소스는 다음과 같이 대응합니다.

| API 리소스 | 운영 콘솔 용어 | 앱 화면 표현 | 설명 |
| --- | --- | --- | --- |
| `vehicle` | 차량 | 내 차량 | 등록된 차량 한 대 |
| `signal` | 시그널 | (노출 안 함) | 차량이 보고하는 데이터 항목 |
| `command` | 원격 명령 | 빠른 제어 | 차량에 보내는 지시 |
| `campaign` | 캠페인 | 소프트웨어 업데이트 | 배포 단위 |
| `sensor` | 센서 | (노출 안 함) | VELA Sense로 장착된 센서 모듈 |
| `zone` | 존 | (노출 안 함) | 차량 내 물리적 구역 (전방·후방·좌측·우측) |

## 시스템 안에서 맡는 자리

![VELA Vehicle API가 시스템 전체에서 담당하는 구간](/img/api-architecture.svg)

이 API는 VELA Cloud와 외부 애플리케이션 사이의 경계입니다. CCU 이하의 차량 내부 통신(존 ECU, VELA Sense와의 통신)은 이 API의 범위 밖이며, VELA OS가 처리합니다. 차량 내부 시그널 버스에 접근하는 C++ SDK도 이 REST API의 범위에 포함되지 않습니다.

## 시작 경로 선택하기

VELA Vehicle API는 직접 REST 요청을 보내는 방법과 공식 SDK를 사용하는 방법을 제공합니다. 다음 중 연동 방식에 맞는 경로로 시작하십시오.

| 연동 방식 | 먼저 읽을 곳 | 이후 참고할 곳 |
| --- | --- | --- |
| **REST API 직접 호출** | [인증 설정하기](./authentication.md) → [REST API 빠르게 시작하기](./quickstart.md) | 기능별 장의 `curl` 예제 |
| **공식 Cloud SDK 사용** | [인증 설정하기 · 클라이언트 등록하기](./authentication.md#1-클라이언트-등록하기) → [SDK로 연동하기](./sdk.md) | 기능별 장과 [SDK 메서드 대응표](./sdk.md#rest-동작과-sdk-메서드) |

Python·Node.js·Java SDK는 VELA Cloud의 REST API를 호출합니다. SDK는 토큰 발급과 갱신을 처리하므로, SDK를 선택한 개발자는 `curl` 기반 퀵스타트를 먼저 수행할 필요가 없습니다.

## 구현 전에 알아야 할 것

아래 세 가지는 일반적인 웹 API와 다른 부분입니다. 특히 스테이징 환경의 동작만 기준으로 구현하면 프로덕션에서 실패할 수 있습니다.

### 차량은 항상 연결되어 있지 않습니다

지하 주차장에 있거나 배터리 보호 모드에 들어가면 통신이 끊깁니다. 그래서 이 API의 조회는 "차량에 지금 물어보는" 것이 아니라 **차량이 마지막으로 보고한 값을 돌려주는** 방식입니다. 시그널의 최신값 응답에는 마지막 보고 시각인 `timestamp`가 함께 옵니다.

:::info[주의]
`timestamp`와 `stale`을 확인하지 않고 값을 표시하면 과거의 배터리 잔량을 현재 값처럼 보여 줄 수 있습니다. 마지막 보고 시각과 데이터 갱신 상태를 함께 처리하십시오. 자세한 응답 예시는 [최신값 조회하기](./vehicle-data.md#최신값-조회하기)를 참고하십시오.
:::

### 원격 명령은 즉시 끝나지 않습니다

조회와 달리 명령은 결과를 바로 돌려주지 않습니다. 요청을 보낸 시점과 차량이 실제로 수행한 시점 사이에 네 단계가 있습니다.

![원격 명령이 비동기로 처리되는 과정](/img/api-command-flow.svg)

**2단계와 4단계는 다른 사건입니다.** 2단계에서 돌아오는 `command_id`는 접수 번호이고, 명령의 결과는 4단계에서 폴링이나 웹훅으로 따로 확인해야 합니다. 3단계에서 차량이 연결되어 있지 않으면 명령은 대기열에 머물다가 만료됩니다.

:::warning[경고]
`202 Accepted`는 요청을 받았다는 뜻일 뿐, 차량이 명령을 수행했다는 뜻이 아닙니다. 이 응답을 성공으로 처리하지 마십시오.
:::

자세한 처리 방식은 [원격 명령 보내기](./remote-commands.md)에 있습니다.

### 스테이징은 사전 조건을 검사하지 않습니다

스테이징 환경의 시뮬레이션 차량은 `vehicle_id`가 `sim_`으로 시작합니다. 원격 명령을 보내면 2초의 지연 후 **항상 성공 응답**을 반환하며, 주차 여부나 배터리 잔량 같은 사전 조건 검사는 건너뜁니다.

:::warning[경고]
이 때문에 "주차 상태가 아니어서 실패" 같은 응답을 프로덕션에서 처음 만나게 됩니다. 실패 경로는 [명령별 사전 조건](./remote-commands.md#명령별-사전-조건)과 [에러 코드](./reference.md#에러-코드)를 보고 미리 구현하십시오.
:::

## 요청과 응답 형식

| 항목 | 규격 |
| --- | --- |
| 프로토콜 | HTTPS만 지원. **TLS 1.2 이상** |
| 요청 본문 | `application/json`, UTF-8 |
| 응답 본문 | `application/json`, UTF-8 |
| 시각 | RFC 3339 (`2026-03-04T18:22:31Z`). 모든 시각은 UTC |
| 단위 | SI 단위. 거리 km, 온도 °C, 전력 kW, 비율 percent |
| 식별자 | 문자열. 숫자로 파싱하지 마십시오 |
| 알 수 없는 필드 | 응답에 새 필드가 추가될 수 있습니다. 무시하도록 구현하십시오 |

## 환경

| 환경 | 기본 URL | 용도 |
| --- | --- | --- |
| 스테이징 | `https://api.staging.vela.example.com/v1` | 통합 개발과 테스트. 시뮬레이션된 차량 데이터를 반환합니다 |
| 프로덕션 | `https://api.vela.example.com/v1` | 실제 차량과 통신합니다 |

자격 증명은 환경마다 별도로 발급받아야 합니다. 스테이징 토큰은 프로덕션에서 동작하지 않습니다.

## SDK

VELA Cloud용 공식 SDK는 **Python, Node.js, Java**를 지원합니다. 토큰 발급·갱신, 조회 요청의 재시도, 비동기 명령 결과 대기 등을 처리합니다. 차량 내부에서 사용하는 C++ SDK는 다른 인터페이스이므로 이 가이드의 범위에서 제외합니다.

[SDK로 연동하기](./sdk.md)에서 설치와 첫 조회 예제를 확인할 수 있습니다. 기능별 장은 `curl`을 기준으로 설명하며, SDK에 대응하는 메서드는 [REST 동작과 SDK 메서드](./sdk.md#rest-동작과-sdk-메서드)에 모았습니다.

## 버전 정책

- API 버전은 URL 경로(`/v1`)로 표시합니다.
- 하위 호환을 깨는 변경(필드 제거, 타입 변경, 필수 파라미터 추가)이 있을 때만 버전을 올립니다. 필드 추가는 버전을 올리지 않습니다.
- 이전 버전은 새 버전 출시 후 **최소 18개월** 지원합니다. 지원 종료 6개월 전에 등록된 이메일로 안내합니다.
- 지원 종료 일정은 [레퍼런스 · 변경 이력](./reference.md#변경-이력)에서 확인할 수 있습니다.
