# VELA Deploy란

VELA Deploy는 차량 소프트웨어를 **한 번에 전부 보내지 않고 단계적으로** 배포하는 운영 콘솔입니다.

차량 소프트웨어 배포는 앱 스토어 업데이트와 다릅니다. 잘못된 소프트웨어가 설치되면 차량이 멈추거나 시동이 걸리지 않을 수 있고, 되돌리는 데 며칠이 걸립니다. 그래서 전체 차량에 바로 보내지 않고 **소수에 먼저 보내 결과를 확인한 뒤 범위를 넓힙니다.**

![배포 범위를 1퍼센트에서 100퍼센트까지 단계적으로 넓히는 과정](/img/deploy-staged-rollout.svg)

:::note[참고]
각 단계 사이의 게이트가 성공률과 오류율로 다음 단계 진행 여부를 자동 판정합니다.
:::

이 판단을 사람이 매번 눈으로 하지 않도록, 각 단계 사이에 **게이트**를 두고 성공률과 오류율로 자동 판정합니다.

## 핵심 개념

배포와 관련된 모든 판단은 아래 다섯 가지 개념 위에서 이루어집니다.

| 개념 | 설명 |
| --- | --- |
| **패키지** | 차량에 설치되는 소프트웨어 묶음. 서명이 검증되어야 배포할 수 있습니다 |
| **캠페인** | 하나의 패키지를 정해진 대상에 배포하는 단위 |
| **타깃 그룹** | 배포 대상 차량의 조건. 차종, 하드웨어 구성, 현재 버전으로 정의합니다 |
| **롤아웃 단계** | 대상을 넓혀 가는 순서. 예를 들어 1% → 10% → 100%입니다 |
| **게이트** | 다음 단계로 넘어갈지 판단하는 기준. 성공률과 오류율로 정의합니다 |

이 다섯 가지의 관계는 다음과 같습니다.

![패키지와 타깃 그룹이 캠페인을 이루고 롤아웃 단계로 이어지는 관계](/img/deploy-concept-map.svg)

**패키지와 타깃 그룹은 캠페인보다 먼저 존재합니다.** 같은 패키지를 다른 타깃 그룹에 보내는 캠페인을 여러 개 만들 수 있고, 반대로 같은 타깃 그룹에 여러 패키지를 순차로 보낼 수도 있습니다.

## 검증 환경과 프로덕션 환경

VELA Deploy에는 환경이 두 개 있습니다. 같은 콘솔에서 위쪽 환경 선택기로 전환합니다.

| 환경 | 대상 차량 | 쓰임 |
| --- | --- | --- |
| **검증 환경** | 사내 검증 플릿 | 캠페인 설정을 실제로 돌려 보고 확인합니다 |
| **프로덕션 환경** | 고객에게 판매된 실제 차량 | 실제 배포를 수행합니다 |

**프로덕션 배포**는 프로덕션 환경에서 시작하는 배포를 말합니다. 고객 차량에 직접 영향을 주기 때문에 검증 환경과 달리 승인이 필요하고, 감사 기록도 더 길게 보관됩니다.

:::warning[경고]
새 캠페인은 반드시 검증 환경에서 먼저 돌려 보십시오. 프로덕션 환경에서 바로 시작하면 설정 실수가 고객 차량에 그대로 적용됩니다.
:::

## 차량 쪽에서 무슨 일이 일어나나

콘솔에서 "배포"를 누른다고 소프트웨어가 바로 설치되는 것이 아닙니다.

| 콘솔에서 보이는 상태 | 차량에서 실제로 일어나는 일 |
| --- | --- |
| 배포 중 | 차량이 파일을 내려받는 중. 주행 중에도 진행됩니다 |
| 설치 대기 | 내려받기는 끝났고, **차량이 주차되기를 기다리는 중**입니다 |
| 설치 중 | 차량에 적용하는 중. 이 동안 차량을 쓸 수 없습니다 |
| 완료 | 적용되고 차량이 결과를 보고한 상태 |

:::info[주의]
설치 대기 상태가 길어지는 것은 보통 실패가 아닙니다. 차량이 주차되지 않았거나 배터리 잔량이 부족한 것입니다. 사전 조건은 [배포 준비하기](./prepare.md#사전-조건-설정하기)에서 정합니다.
:::

차량 소유자가 보는 화면은 [VELA Drive 앱 · 소프트웨어 업데이트 하기](../app/software-update.md)에 있습니다.
