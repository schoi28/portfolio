# 다이어그램·픽토그램 가이드라인

이 문서는 VELA 문서 세트에 들어가는 모든 그림의 제작 기준입니다. `glossary.csv`가 용어의 기준인 것처럼, 이 문서는 그림의 기준입니다.

그림은 전부 손으로 작성한 SVG입니다. 디자인 도구에서 내보내지 않으므로, 일관성은 도구가 아니라 **이 문서의 수치를 지키는 것**에서만 나옵니다. "간격을 비슷하게"가 아니라 "수직 간격 24"로 적혀 있어야 다음에 만드는 그림이 지금 것과 같아집니다.

---

## 1. 그림의 역할

그림은 **글로 설명하면 길어지는 공간적·시간적 관계**를 대신합니다. 그 외의 목적으로는 쓰지 않습니다.

| 쓴다 | 쓰지 않는다 |
| --- | --- |
| 구성 요소 사이의 연결과 경계 | 글로 한 문장이면 되는 내용 |
| 시간 순서가 있는 흐름 | 표로 정리하는 편이 나은 대응 관계 |
| 물리적 배치와 방향 | 장식 |
| 부품 식별 | 경고·주의 |

### 금지: 이미지에만 있는 정보

그림 안의 글자는 **검색되지 않고, 번역되지 않으며, 스크린리더가 읽지 못하고, 확대하면 깨집니다.** 따라서 그림이 전달하는 내용은 반드시 본문에도 있어야 합니다. 그림은 본문을 **보조**하지 대체하지 않습니다.

이 원칙의 직접적인 결과가 다음 두 규칙입니다.

**경고·주의는 그림에 넣지 않습니다.** 안전이나 데이터 손실에 관한 지시는 안내 상자(`:::danger` `:::warning` `:::info`)에만 둡니다. 그림에 박힌 경고는 번역본에서 원문 언어로 남고, 스크린리더 사용자에게는 존재하지 않는 것과 같습니다.

**레이블은 명사구로 씁니다.** 서술어·명령형·마침표를 쓰지 않습니다.

| 안 됨 | 됨 |
| --- | --- |
| 여기서 성공으로 처리하면 안 됩니다 | (삭제 후 본문 안내 상자로) |
| 연결이 끊겨 있으면 대기열에서 만료 | 미연결 시 대기열 만료 |
| 차량이 수행하고 결과 보고 | 차량 수행 · 결과 보고 |
| 폴링 또는 웹훅으로 결과 확인 | 폴링 · 웹훅 |

## 2. 캔버스와 그리드

### 기준 단위

모든 좌표는 **4의 배수**, 박스의 모서리 좌표와 크기는 **8의 배수**입니다. 8px 베이스 그리드입니다.

소수점 좌표를 쓰지 않습니다. `x="380.0"`은 `x="380"`으로 적습니다.

### 캔버스 폭은 밀도를 뜻합니다

그림은 본문에서 **칼럼 폭에 맞춰 늘어나거나 줄어듭니다.** SVG의 `width` 속성이 그려지는 크기를 정하지 않습니다 (`src/components/Figure.js`가 `width: 100%`를 적용합니다).

본문 칼럼은 사이드바와 목차를 빼고 **약 750px**입니다. 따라서 캔버스 폭은 "얼마나 크게 보이는가"가 아니라 **"얼마나 빽빽하게 보이는가"**를 정합니다. 캔버스가 넓을수록 같은 글자가 더 작게 그려집니다.

```
실효 폰트 크기 = 폰트 크기 × (750 ÷ 캔버스 폭)
```

| 폭 | 배율 | 11px의 실효 크기 | 용도 |
| --- | --- | --- | --- |
| **640** | ×1.17 | 12.9px | 단계 흐름, 상태 전이 등 요소가 적은 그림 |
| **760** | ×0.99 | 10.9px | 기본값. 흐름도, 개념도, 배선도 |
| **900** | ×0.83 | 9.2px | 부품 카탈로그, 격자 배치. **하한** |

**900을 넘지 않습니다.** 1200px 캔버스에서는 11px이 실효 6.9px이 되어 본문에서 읽을 수 없습니다. 담을 내용이 많으면 **폭을 늘리지 말고 세로로 길게 가거나 그림을 나눕니다.** 세로는 늘려도 글자 크기에 영향이 없습니다.

높이는 자유지만 **8의 배수**로 맞춥니다.

### 라이트박스는 보완이지 전제가 아닙니다

모든 그림은 눌러서 확대할 수 있습니다 (최대 1200px). 밀도가 높은 그림의 세부를 확인하는 용도입니다.

그러나 **본문 크기에서 읽히지 않는 그림은 확대해도 실패입니다.** 독자는 읽히지 않는다는 사실을 알아야 누를 생각을 합니다. 라이트박스를 이유로 캔버스를 넓히지 않습니다.

### 외곽 여백

캔버스 가장자리에서 **24px 안쪽**까지는 아무것도 두지 않습니다.

그리고 **캔버스 폭은 내용의 실제 폭에 맞춥니다.** 내용이 620px에서 끝나는데 캔버스가 760px이면 오른쪽에 140px의 빈 공간이 생기고, 그림이 왼쪽으로 쏠려 보입니다. 내용을 먼저 배치하고, `실제 폭 + 48`을 표의 네 값 중 가장 가까운 것으로 올림합니다. 남는 여백은 좌우로 똑같이 나눕니다.

### 간격

| 항목 | 값 |
| --- | --- |
| 박스 내부 좌우 패딩 | 16 |
| 박스 내부 상하 패딩 | 12 |
| 세로로 쌓인 박스 사이 | 24 (화살표가 들어가는 공간) |
| 가로로 놓인 박스 사이 | 32 |
| 박스와 주석 사이 | 24 |
| 영역 테두리와 내부 요소 사이 | 20 |

## 3. 타이포그래피

### 폰트

```css
font-family: 'Pretendard', -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif;
```

국문판과 영문판 모두 같은 스택을 씁니다. Pretendard는 라틴 문자도 포함합니다.

### 스케일

**네 가지만 사용합니다.** 중간값을 새로 만들지 않습니다.

| 역할 | 크기 | 굵기 | 색 | 행간 |
| --- | --- | --- | --- | --- |
| 영역 헤더 | 14px | 700 | `ink` | 20 |
| 박스 제목 | 13px | 600 | `ink` | 18 |
| 보조 레이블 | 11px | 400 | `ink-muted` | 16 |
| 주석·수치 | 11px | 700 | `line-strong` | 16 |

**11px 미만을 쓰지 않습니다.** 문서 본문 폭에서 축소 렌더링될 때 읽을 수 없게 됩니다.

영역 헤더에만 `letter-spacing: 0.04em`을 적용합니다. 나머지는 0입니다.

### 줄 수와 길이

| 항목 | 상한 |
| --- | --- |
| 한 레이블의 줄 수 | 2줄 |
| 한 줄 길이 (국문) | 20자 |
| 한 줄 길이 (영문) | 28자 |

#### 영문 레이블의 대소문자

가운뎃점(`·`)으로 이어진 항목은 **대등한 관계**이므로 전부 대문자로 시작합니다. 앞만 대문자로 쓰면 뒤의 것이 종속된 것처럼 읽힙니다.

| 안 됨 | 됨 |
| --- | --- |
| Battery · range | Battery · Range |
| Lock · climate · charging | Lock · Climate · Charging |
| Cellular · mTLS · drops possible | Cellular · mTLS · Drops possible |

식별자 · 명령어 · 프로토콜 이름은 **제품이 쓰는 표기를 그대로** 둡니다. 대문자 규칙을 적용하지 않습니다.

- `command_id · Not yet run` — 식별자
- `Node 20 · npm ci` — 명령어
- `Cellular · mTLS · Drops possible` — 프로토콜 이름

상한을 넘으면 레이블을 줄이지 말고 **그 정보를 본문으로 옮깁니다.**

### 세로 정렬

`dominant-baseline`을 쓰지 않습니다. 브라우저마다 결과가 다릅니다. 베이스라인 좌표를 직접 계산합니다.

- 1줄: 박스 중심 y + 4
- 2줄: 첫 줄은 중심 y − 4, 둘째 줄은 중심 y + 13

## 4. 색상

### 토큰

**8개만 사용합니다.** 새 헥스값을 도입하지 않습니다.

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `ink` | `#0f1419` | 제목 텍스트 |
| `ink-muted` | `#6b7681` | 보조 레이블 |
| `line` | `#b9c0c8` | 기본 테두리 |
| `line-strong` | `#3d4852` | 연결선, 화살표, 주석 |
| `surface` | `#ffffff` | 박스 바탕 |
| `canvas` | `#f5f7f8` | 캔버스 바탕, 비활성 박스 바탕 |
| `fill-muted` | `#e4e9ec` | 물리 객체의 면 |
| `accent` | `#1f3a5f` | 설명 대상, 범위 강조 |
| `caution` | `#9c5f14` | 오해하기 쉬운 지점, 되돌릴 수 없는 동작 |
| `danger` | `#9b3a34` | 실패·중단 경로 |

### 강조색은 본문의 안내 상자 등급과 맞춥니다

그림에서 어떤 요소를 강조할지는 취향이 아니라 **그 내용이 본문에서 어떤 등급으로 다뤄지는지**를 따릅니다. 같은 사안이 본문에서는 주의인데 그림에서는 빨간색이면 독자가 심각도를 잘못 읽습니다.

| 그림의 색 | 본문 대응 | 쓰는 경우 |
| --- | --- | --- |
| `accent` | — | 이 그림이 설명하려는 대상, 문서의 범위 경계 |
| `caution` | `:::info[주의]` `:::warning[경고]` | 독자가 **오해하기 쉬운 지점**. 실패는 아니지만 잘못 읽으면 문제가 되는 단계 |
| `danger` | `:::danger[위험]` | 실제로 **실패하거나 중단되는** 경로 |

`202 Accepted`가 그 예입니다. 실패가 아니라 **성공으로 오해되는 접수 상태**이므로 `danger`가 아니라 `caution`입니다. 빨간색을 쓰면 "에러 응답"으로 읽힙니다.

### 사용 규칙

**강조색은 한 그림에 최대 두 종류**, 각각 **한 곳에만** 씁니다. 세 곳을 강조하면 어느 곳도 강조되지 않습니다.

**강조는 테두리와 배지를 함께** 바꿉니다. 테두리만 바꾸면 축소 렌더링에서 보이지 않습니다.

### 색이 정보를 나르는 경우

위의 강조는 "여기를 보라"는 **시각적 비중**이고, 정보 자체는 레이블과 본문에 있습니다. 이 경우 색만 써도 됩니다.

그러나 **색이 구분해야 할 정보 자체를 나를 때**는 색 외의 단서를 반드시 함께 둡니다. 성공 경로와 실패 경로, LED 상태처럼 색이 곧 의미인 경우입니다.

| 정보 | 색 외의 단서 |
| --- | --- |
| 실패·분기 경로 | 점선 `stroke-dasharray="6 4"` |
| 상태 구분 | 레이블 병기 |
| 범주 구분 | 범례 (10절) |

색각 이상이 있어도, 흑백으로 인쇄해도 구분되어야 합니다.

### 폐기한 값

아래 값은 더 이상 쓰지 않습니다. 기존 파일에서 발견하면 오른쪽으로 바꿉니다.

| 폐기 | 대체 |
| --- | --- |
| `#dfe3e8` `#e7ecf1` `#cdd5da` | `fill-muted` |
| `#9c4a3c` `#7a2d28` `#c0453f` `#8a2f2a` | `danger` |
| `#4a5a6b` `#3a4552` `#2a3340` | `line-strong` |
| `#f6eded` | `surface` |
| `#d9892a` `#2f8f6b` `#1d6b4f` | LED 상태 색은 `sensor-led-states` 한 곳만 예외 |

## 5. 도형

### 선 굵기

| 용도 | 값 |
| --- | --- |
| 박스 테두리 | 2 |
| 연결선, 화살표 | 2 |
| 내부 구분선 | 1.5 |

세 가지 외에는 쓰지 않습니다.

### 모서리

| 대상 | rx |
| --- | --- |
| 논리적 요소 (시스템, 상태, 단계) | **0** |
| 물리적 객체 (기기, 커넥터, 보드) | **4** |
| 번호 배지, 알약형 라벨 | 높이의 절반 |

### 화살표

파일마다 하나의 마커만 정의하고 재사용합니다. 색이 다른 화살표가 필요하면 마커를 복제하되 기하는 동일하게 둡니다.

```xml
<marker id="arrow" markerWidth="8" markerHeight="8" refX="8" refY="4" orient="auto">
  <path d="M0 0L8 4L0 8z" fill="#3d4852"/>
</marker>
```

`refX`는 **8**입니다. 화살촉의 끝이 경로의 끝 좌표에 정확히 놓입니다.

#### 박스에 붙입니다

연결선의 시작과 끝은 **박스의 변 좌표 그대로**입니다. 띄우지 않습니다.

```
박스 A가 y=88에서 끝나고 박스 B가 y=112에서 시작하면
→ d="M320 88V112"   (길이 24)
```

어떤 화살표는 붙어 있고 어떤 화살표는 떨어져 있으면, 붙은 쪽이 다른 관계처럼 보입니다. 간격을 두고 싶다면 박스 사이 간격 자체를 조정합니다.

#### 길이는 간격과 같습니다

화살표 길이는 2절의 간격 값에서 나옵니다. 그림마다 다르게 잡지 않습니다.

| 방향 | 길이 |
| --- | --- |
| 세로 (쌓인 박스 사이) | 24 |
| 가로 (나란한 박스 사이) | 32 |
| 영역과 영역 사이 | 40 |
| 설명이 얹히는 세로 화살표 | 48 |

아래 값은 **기본값**입니다. 박스가 다섯 개 이상이면 폭과 간격이 딱 떨어지지 않습니다. 이때는 다음 순서로 조정합니다.

1. 박스 폭을 줄여 기본 간격을 맞춥니다.
2. 그래도 안 되면 간격을 **4의 배수**로 바꾸되, **한 그림 안에서는 모두 같게** 둡니다.

좌우 여백 24를 깨면서까지 기본값을 지키지 않습니다. 눈에 보이는 것은 간격이 32인지가 아니라 **간격이 들쭉날쭉한지**입니다.

#### 설명이 붙는 화살표

화살표에 설명이 붙으면 **선의 가운데에 놓고, 글자가 놓이는 만큼 선을 가립니다.** 선 옆에 흘려 두면 어느 화살표의 설명인지 읽히지 않고, 선이 글자를 가로지르면 읽기 어렵습니다.

```xml
<!-- 선을 먼저 그리고, 캔버스색 사각형으로 가린 뒤, 그 위에 글자를 둡니다 -->
<path d="M380 300V340" .../>
<rect x="..." y="..." width="글자 폭 + 24" height="18" fill="#f5f7f8"/>
<text ... text-anchor="middle">셀룰러 · mTLS · 단절 가능</text>
```

| 항목 | 값 |
| --- | --- |
| 글자 좌우 여백 | 12 |
| 가림 사각형 높이 | 18 |
| 가림 사각형 채움 | 캔버스색 `#f5f7f8` |

**세로 화살표에 설명이 붙으면 길이를 48로 잡습니다.** 40으로는 가림 사각형(높이 18)이 선의 절반을 먹어 화살표가 토막처럼 보입니다.

**가로 화살표에 설명이 붙으면 화살표를 늘립니다.** 기본 길이 32로는 설명이 선보다 길어져 화살표가 글자에 묻힙니다. 이때만 길이를 `설명 폭 + 48`로 잡습니다.

가림 사각형은 배경과 같은 색이므로 **넓게 잡아도 보이지 않습니다.** 글자 폭을 어림할 때는 넉넉한 쪽으로 잡으십시오. 좁게 잡으면 선이 글자 사이로 비칩니다.

## 6. 배치도

차량 상면도나 캘리브레이션 타깃 배치처럼 **실제 공간을 그리는 그림**은 박스와 화살표로 된 그림과 규칙이 다릅니다. 2~5절은 그대로 따르되, 아래를 더합니다.

### 비율

실측 도면이 아닙니다. **비율을 흉내 내되 수치는 반드시 글자로 적습니다.** 독자가 그림에서 길이를 재게 두어서는 안 됩니다.

### 지시선

부품에서 레이블로 잇는 선입니다. 화살촉을 붙이지 않습니다. 부품을 가리키는 선이지 흐름이 아닙니다.

| 항목 | 값 |
| --- | --- |
| 꺾임 | 수직·수평만. 사선 금지 |
| 선 | `line-strong` 2px |
| 부품과 선 사이 | 붙입니다 |
| 선 끝과 글자 사이 | 8 |

### 레이블 자리

**지시선 레이블은 그림의 한쪽에 모읍니다.** 양쪽으로 흩으면 긴 레이블이 캔버스 밖으로 나가고, 번역하면 더 길어집니다.

한쪽에 다 넣을 수 없으면, 짧은 레이블 하나만 반대쪽에 두고 나머지는 모읍니다. **영문 레이블 기준으로 자리를 잡으십시오.**

### 치수선

| 항목 | 값 |
| --- | --- |
| 끝 표시 | 짧은 수직선 (길이 16) |
| 선 | `ink-muted` 2px |
| 수치 | 선 가운데. 5절의 가림 규칙을 그대로 적용 |

### 면으로 표시하는 영역

센서 시야처럼 **범위를 뜻하는 영역**은 화살표가 아니라 면으로 그립니다. `fill-muted`로 채우고 테두리는 두지 않습니다.

## 7. 픽토그램

부품이나 기기를 그림으로 식별시킬 때 씁니다. 라이다와 카메라처럼 **글자만으로는 어느 것인지 알 수 없는 물건**에만 쓰고, 장식으로 쓰지 않습니다.

픽토그램이 아마추어처럼 보이는 이유는 디테일이 적어서가 아니라 **제작 기준이 없어서**입니다. 아래를 지키면 같은 사람이 그린 한 벌로 보입니다.

### 제작 격자

모든 픽토그램은 **48 × 48 격자**에 그린 뒤 `transform`으로 배치합니다. 파일마다 다른 크기로 직접 그리지 않습니다.

| 항목 | 값 |
| --- | --- |
| 격자 | 48 × 48 |
| 여백 | 사방 4 |
| 실제 영역 | 40 × 40 |

### 키라인

물건의 성격에 따라 넷 중 하나에 맞춥니다. 격자를 꽉 채우려 하지 마십시오. 길쭉한 물건과 네모난 물건이 같은 면적으로 보여야 합니다.

| 키라인 | 크기 | 쓰는 물건 |
| --- | --- | --- |
| 정사각 | 40 × 40 | 박스, 보드 |
| 원 | 지름 40 | 렌즈, 회전체 |
| 세로 | 28 × 40 | 휴대폰, 카트리지 |
| 가로 | 40 × 28 | 케이블, 브래킷 |

### 선

**선만 씁니다.** 면으로 채운 픽토그램과 선으로 그린 픽토그램을 섞지 않습니다.

| 항목 | 값 |
| --- | --- |
| 굵기 | 2 |
| 색 | `line-strong` |
| 모서리 | `stroke-linejoin="round"` |
| 끝 | `stroke-linecap="round"` |
| 덩어리 표현 | `fill-muted`로만. 테두리는 그대로 2px |

**`stroke-linejoin="round"`가 가장 큰 차이를 만듭니다.** 각진 모서리가 그대로 남으면 도면처럼 보이고, 둥글게 처리하면 아이콘처럼 보입니다.

### 꼭 그려야 하는 특징

물건을 **물건으로 알아보게 하는 최소 요소**는 빠뜨리지 않습니다. 디테일을 더하는 것보다 이게 먼저입니다.

| 물건 | 없으면 못 알아보는 것 |
| --- | --- |
| 휴대폰 | 화면 테두리 (바깥 몸체만 있으면 그냥 사각형) |
| 차량 상면도 | 앞유리 · 뒷유리 · 바퀴 (없으면 덩어리) |
| 카메라 | 렌즈 |
| 케이블 | 양 끝 커넥터 |
| 라이다 | 광학창 띠 |

### 추상화 수준 통일

한 그림 안의 픽토그램은 **같은 수준으로 단순화**합니다. 하나만 자세하면 그것만 떠 보입니다. 부품 열 개를 그린다면 열 개 모두 같은 수의 선으로 그린다고 생각하십시오.

### 재사용

같은 물건은 파일마다 다시 그리지 않습니다. 한 번 정한 모양을 그대로 씁니다. 라이다가 그림마다 다르게 생기면 같은 물건인지 알 수 없습니다.

---

## 8. 접근성

- 루트 `<svg>`에 `role="img"`와 `aria-label`을 둡니다.
- `aria-label`은 **본문의 대체 텍스트와 같은 문장**으로 적습니다. 두 곳이 다르면 안 됩니다.
- 대체 텍스트는 그림이 **무엇을 보여 주는지** 적습니다. "~ 다이어그램", "~ 그림"으로 시작하지 않습니다.
- 모든 텍스트는 자기 바탕색 대비 **4.5:1 이상**이어야 합니다. 위 토큰 조합은 이를 만족합니다.
- 의미를 색으로만 전달하지 않습니다 (4절 참고).

## 9. 국문판과 영문판

### 방식: 파일 쌍

하나의 그림은 두 파일로 존재합니다.

```
api-command-flow.svg      ← 국문 (sample_docs/)
api-command-flow.en.svg   ← 영문 (i18n/en/)
```

**도형 좌표는 완전히 동일합니다.** 두 파일의 차이는 `<text>` 요소의 내용과 `aria-label`뿐입니다. 박스 위치나 크기를 한쪽만 고치지 않습니다.

#### 두 언어에서 달라도 되는 좌표

글자 폭에서 바로 계산되는 **두 가지뿐**입니다. 그 외에 좌표가 다르면 어느 한쪽을 잘못 고친 것입니다.

| 허용 | 이유 |
| --- | --- |
| 범례의 시작 x | 항목 전체 폭이 달라 가운데 정렬 결과가 달라집니다 |
| 화살표 설명 가림 사각형의 x · width | 글자 폭만큼 가려야 합니다 |

### 영문 기준으로 먼저 설계합니다

같은 내용을 적으면 **영문이 국문보다 약 1.3배 깁니다.** 국문 기준으로 박스 폭을 정하면 영문판에서 반드시 넘칩니다.

따라서 **영문 레이블을 먼저 쓰고, 그 폭에 맞춰 박스를 설계한 뒤, 국문을 그 안에 넣습니다.** 국문판에 약간의 여백이 남는 것은 정상입니다.

### `<switch systemLanguage>`를 쓰지 않는 이유

`<img>`로 참조된 SVG는 **브라우저의 언어 설정**을 따르지 사이트의 로케일을 따르지 않습니다. 한국어 브라우저로 영문 사이트를 보면 한국어가 나옵니다. 사용하지 않습니다.

### 글자가 없는 그림

부품 카탈로그처럼 **번호와 수치만으로 성립하는 그림**은 한 파일로 두 언어를 모두 처리합니다 (`sensor-kit-items.svg`). 이때 번호의 뜻은 본문 표가 설명합니다.

단, **흐름도에는 이 방식을 쓰지 않습니다.** 단계마다 표를 찾아보게 만들면 그림의 목적이 사라집니다.

## 10. 범례

### 범례를 두는 경우

범례는 **색이나 선 모양이 레이블로 설명할 수 없는 정보를 나를 때만** 둡니다. 요소마다 레이블이 붙어 있다면 범례는 중복입니다.

| 둔다 | 두지 않는다 |
| --- | --- |
| 같은 색이 여러 요소에 반복되고, 그 색이 범주를 뜻할 때 | 요소가 서너 개뿐이고 각각 레이블이 있을 때 |
| 실선과 점선이 서로 다른 경로를 뜻할 때 | 색을 강조 용도로만 썼을 때 |

### 위치

**항상 그림의 맨 아래, 가로 중앙 정렬입니다.** 예외를 두지 않습니다. 범례가 그림마다 다른 자리에 있으면 독자가 매번 찾아야 합니다.

| 항목 | 값 |
| --- | --- |
| 마지막 내용과 범례 사이 | 24 |
| 범례와 캔버스 아래 끝 사이 | 24 |
| 항목 사이 | 24 |
| 색 견본 크기 | 12 × 12 |
| 선 견본 길이 | 20 |
| 견본과 레이블 사이 | 8 |
| 레이블 | 11px / 400 / `ink-muted` |

범례를 박스로 감싸지 않습니다. 테두리를 두르면 그림의 일부처럼 보입니다.

### 중앙 정렬 계산

항목 전체의 폭을 더한 뒤 캔버스 중심을 기준으로 배치합니다.

```
전체 폭 = Σ(견본 + 8 + 레이블 폭) + 24 × (항목 수 − 1)
시작 x  = (캔버스 폭 − 전체 폭) ÷ 2
```

레이블 폭은 11px 기준 **국문 11px/자, 영문 6px/자**로 어림합니다.

## 11. 파일 규칙

### 이름

```
<문서세트>-<내용>.svg
<문서세트>-<내용>.en.svg
```

`api-` `app-` `deploy-` `sensor-` `vela-` 접두어를 씁니다. 소문자와 하이픈만 사용합니다.

### 머리 주석

모든 파일은 다음 주석으로 시작합니다.

```xml
<!--
  api-command-flow · 원격 명령의 비동기 처리 단계
  사용처: sample_docs/api/overview.md
  쌍: api-command-flow.en.svg
  기준: _config/diagram-guidelines.md
-->
```

### 루트 속성

`viewBox`와 `width`·`height`를 모두 둡니다. 파일을 단독으로 열었을 때의 기본 크기가 됩니다.

다만 **본문에서는 이 값이 무시됩니다.** `src/components/Figure.js`가 `width: 100%`로 칼럼을 채웁니다. 그림이 작아 보인다고 `width` 속성을 키우지 마십시오. 아무 효과가 없습니다. 밀도를 바꾸려면 `viewBox`의 폭을 바꿔야 합니다.

### 검수 항목

새 그림을 만들거나 고친 뒤 확인합니다.

- [ ] 캔버스 폭이 640 · 760 · 900 중 하나인가
- [ ] 실효 폰트 크기가 9px 이상인가
- [ ] 외곽 24px 안에 요소가 없는가
- [ ] 좌우 여백이 같은가
- [ ] 폰트 크기가 네 종류 안에 있는가
- [ ] 색이 토큰 안에 있는가
- [ ] 강조색이 두 종류 이하이고, 각각 한 곳에만 쓰였는가
- [ ] 강조색 선택이 본문의 안내 상자 등급과 맞는가
- [ ] 모든 `<text>`에 `text-anchor`가 명시되어 있는가
- [ ] 컨테이너 안의 글자가 중심 좌표를 공유하는가
- [ ] 화살표가 박스에 붙어 있고 길이가 간격 값과 같은가
- [ ] 화살표 설명이 선 가운데에 있고 선이 가려져 있는가
- [ ] 영문 레이블에서 `·`로 이어진 항목이 모두 대문자로 시작하는가
- [ ] 제품 이름이 본문·용어집과 같은가
- [ ] 픽토그램이 48 격자·2px 선·둥근 모서리로 통일되어 있는가
- [ ] 픽토그램에 알아보는 데 꼭 필요한 특징이 들어 있는가
- [ ] 범례가 있다면 맨 아래·가로 중앙에 있는가
- [ ] 레이블에 서술어·마침표가 없는가
- [ ] 경고·주의가 그림에 들어 있지 않은가
- [ ] 그림의 정보가 본문에도 있는가
- [ ] `.en.svg` 쌍의 도형 좌표가 동일한가
- [ ] `aria-label`과 본문 대체 텍스트가 **글자 그대로** 같은가
- [ ] 실제로 렌더해서 눈으로 확인했는가
